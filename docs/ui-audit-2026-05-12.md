# UI audit — 2026-05-12

Sweep across every page + component. Findings grouped by category. The
reported header overlap is in #1, fix shipped in the same batch.

## 1. Layout bugs (fix first)

### 1.1 Header overlap on mid-width desktop — FIXED
**Reproducer:** viewport between ~1100-1300px on the homepage.
**Symptom:** `HOW IT WORKS` and `FAQ` overflow the center grid column
and clip under the right-side Search button (the screenshot you showed).
**Cause:** the 3-column CSS grid (`sm:grid sm:grid-cols-3`) gives the
center column a fixed proportional width, but the nav at min-content can
exceed it; the right column then renders on top.
**Fix:** dropped `HOW IT WORKS` + `FAQ` from the top nav. They live as
homepage scroll anchors AND in the footer; the top nav doesn't need them
for navigation. The remaining 4 items fit comfortably at every
breakpoint.

### 1.2 Hero floating icons clip behind page chrome on narrow desktop
The `CreateFloatingIcons` and `MyTicketsFloatingIcons` are
absolutely-positioned around the hero band. They overflow the visible
area on viewports < ~720px wide; some icons end up half off-screen and
clipped. Not a bug per se but visually messy.
**Suggest:** mask the right/bottom strips with the `bg-dots` mask
boundary so the icons fade out gracefully when they extend past content.

### 1.3 CreatePoolModal cancel button + title may collide on phone
On viewports < 360px wide the "Cancel" button's pill width pushes the
"PARAMETERS" title down. The `<dialog>` is `max-w-[min(92vw,640px)]`
which is correct, but the inner row uses `flex items-start
justify-between gap-4` — at minimum gap the title wraps.
**Suggest:** stack to `flex-col sm:flex-row` so on small screens the
title gets full width above the close button.

### 1.4 Toast position vs ZeroBalanceBanner
Both render at the top of the page tree. The banner sits inside the
header; the toast appears below it. No actual overlap, but the toast's
default position (top-right) collides with the bell badge on narrow
screens. Worth verifying.

## 2. Color palette inconsistency (biggest theme drift)

CSS variables exist in `globals.css`:
```
--mint:     #88cfc4
--lavender: #c9b5dc
--yellow:   #e8d89e
--pink:     #e8a5c0
```

But **18 different files** redeclare these colors as local hex constants:
- `const MINT = "#88cfc4"` appears in: leaderboard, create page,
  notifications, CreatorPanel, FirstConnectPrompt, CreatorDashboard,
  CreatePoolModal, SearchPalette, ProfileCard, PoolInviteBanner,
  FriendPicker, InviteFriendsTab, FriendsDrawer, HostRaffleSection, …
- `const LAVENDER`, `const YELLOW`, `const PINK`, `const SAND`,
  `const CORAL` similarly fragmented.

**Casing drift:** `#E89999` (uppercase E) vs `#e89999` (lowercase) both
appear in the same project for the same color. Some places call it
`PINK`, others call it `CORAL`. The CSS var `--pink: #e8a5c0` is a
*different* pink that none of the inline constants match.

**Fix:**
1. Add aliases for missing colors to globals.css:
   ```css
   --coral:  #e89999;
   --sand:   #e8d89e;  /* alias of --yellow */
   --rose:   #e8a5c0;  /* current --pink */
   ```
2. Sweep replace inline hex with `style={{ color: "var(--mint)" }}` (or
   add Tailwind utilities `text-mint`, `bg-mint`, `border-mint` mapped
   to CSS vars).
3. Decide canonical names: I'd standardize on `mint / lavender / coral
   / sand / rose`. Drop `LIME` alias entirely (it was a mockup
   carryover that already aliases lavender — confusing).

**Effort:** ~2 hours codemod. Pure cleanup, no visual change.

## 3. Border-radius scale is fragmented

Currently used:
- `rounded-3xl` — CreatePoolModal outer (only)
- `rounded-2xl` — cards, profile card, banners, tile grids
- `rounded-xl` — radio cards, inputs, tile rows, mini-stats
- `rounded-lg` — alert blocks, hamburger, mobile nav rows, input
  variants
- `rounded-full` — buttons, pills, badges, identicons
- `rounded-md` — a couple status-pill stragglers

**Fix:** lock to four levels and document:

| Use | Class |
|---|---|
| Buttons / pills / badges | `rounded-full` |
| Inputs / mini-stat tiles / radio cards | `rounded-xl` |
| Cards / banners / modal panels | `rounded-2xl` |
| Container surfaces (page-level) | none / `rounded-3xl` for true heros |

Specific changes: alert banners currently mix `rounded-lg` and
`rounded-2xl` for visually identical purpose — standardize to `rounded-2xl`.

## 4. Button hierarchy is implicit

Three button shapes coexist but no consistent rule:

1. **Tear-corner CTA** (`btn-fx fx-tear`) — used for major
   transactional actions (Buy ticket, Create pool, Redeem). Heavy
   visual weight; fitting for "this costs SOL".
2. **Filled mint pill** (`rounded-full bg:MINT color:#000`) — used
   for "send invite", "claim", "+Add", "accept request", "set up
   profile". Same weight regardless of how consequential.
3. **Outline pill** (`rounded-full border bg-neutral-950 text-neutral-300`) —
   used for "Edit Profile", "Decline", "Skip", "Cancel".
4. **Bare nav-link** — header nav, back links.

**Issue:** filled mint pill is overloaded — it represents both "submit
this signed action" AND "navigate me there". A user can't tell from
the shape whether a click will trigger a wallet popup.

**Suggest:**
- Reserve **filled mint pill** for actions that trigger a wallet
  signature.
- Use **mint outline pill** for navigation / passive actions.
- Tear-corner CTA stays for SOL-spending actions only.

Codify in a `<Button variant="primary|secondary|cta" />` component to
prevent future drift.

## 5. Typography scale drifts in small text

The "label" text uses `font-mono text-[N]px uppercase tracking-widest`
at sizes:
- `text-[9px]` (small badges, stat sub-labels)
- `text-[10px]` (most labels)
- `text-[11px]` (mode hints, identifiers)
- `text-xs` (12px — admin tables, some buttons)

And neutral color:
- `text-neutral-400` (most muted)
- `text-neutral-500` (secondary)
- `text-neutral-600` (very muted)
- `text-muted-2` (custom CSS var — used in mockup pages only)

**Inconsistency examples:**
- `Stat` tile label = `text-[10px] text-neutral-500`
- `StatTile` tile label = `text-[9px] text-neutral-500`
- `Metric` tile label = `text-[10px] text-neutral-500`
- Why is `StatTile` smaller? Probably historical.

**Suggest:** lock to a 2-level scale:
- **Tier 1 labels** (above big numbers): `text-[10px] text-neutral-500
  uppercase tracking-widest`
- **Tier 2 captions / footnotes**: `text-[10px] text-neutral-600
  uppercase tracking-widest` OR `text-xs text-neutral-500 normal-case`

Drop the `text-[9px]` variant entirely.

## 6. Status pill inconsistency

Multiple "status indicator" patterns:

- **OPEN / DRAWING / RESOLVED / CLOSED** on CreatorDashboard: border
  + bg + colored text, `rounded-full px-2 py-0.5`
- **SENT / REDEEMED** on InviteFriendsTab: plain text in mint/sand
  color, no pill
- **friend-request "FRIENDS"** on ProfileCard ActionButton: solid
  pill with mint bg
- **search-result "Friends" / "Sent"** on SearchPalette: plain text

Same semantic concept (state badge), four visual treatments.

**Suggest:** one shared `<StatusPill kind="open|closed|drawing|resolved|sent|redeemed|friends|pending"
/>` component. Each `kind` maps to a (color, label, optional glyph)
tuple. All status displays import this.

## 7. Identicon vs avatar usage

`WalletIdenticon` is used in 8 places at sizes 20, 28, 32, 40, 48, 72.
Sizes are passed as raw numbers per call. Some places set
`initialOverride`, some don't, some derive it inline.

**Suggest:** sizes as named tokens (`xs/sm/md/lg/xl`) and always
auto-derive `initial` from wallet/pseudo inside the component (already
the default fallback). Cleaner call sites.

## 8. Specific visual nits

### 8.1 The `bg-lime` / `--lime` legacy aliases
`globals.css` has `.bg-lime { background: var(--lavender); }`. This is
a leftover from an old mockup that called the accent color "lime" even
though it's actually lavender. It's never going to be lime green;
either rename to `.bg-lavender` everywhere or remove and use the var
directly.

### 8.2 Footer is mostly empty
The `BentoFooter` is dense but the smaller `<footer>` below it has just
"© 2026" + GitHub. Now that we've removed HOW IT WORKS / FAQ from the
top nav, they should live as footer links.

### 8.3 Inconsistent ghost-button states
`btn ghost` (in the mockup) vs `border border-neutral-800
bg-neutral-900` (rest of app) achieve the same look but have different
hover transitions. Pick one.

### 8.4 Modal close button placement
- CreatePoolModal: top-right outline pill labeled "Cancel" or "Done"
- EditProfileModal: top-right `×` icon
- SearchPalette: no close button (esc only)
- FriendsDrawer: top-right `×` icon

Three different close-affordances. Suggest: standard top-right `×`
icon + esc; pill button only for "Done" success states.

### 8.5 Mode-radio active state contrast
The new 3-card access-mode picker uses mint background + mint border on
active. The mint-on-mint is brand-correct but borderline contrast for
the non-active title color (which is now `#f5f5f5`). Test for
accessibility (4.5:1 contrast ratio).

## 9. Spacing inconsistencies

Within a single component you can see `gap-2`, `gap-2.5`, `gap-3`,
`gap-4` and `space-y-2`, `space-y-3` chosen ad-hoc. Page paddings
(`p-4`, `p-5`, `p-6`, `p-7`) vary between similar card surfaces.

**Suggest:** pick a 4-step scale and document. E.g.:
- Tight (badges, inline): `gap-1.5`
- Default (lists, cards): `gap-3`
- Section gaps: `gap-6`
- Major page gaps: `gap-12`

Same idea for paddings.

## 10. Accessibility quick wins

- Some `aria-label` strings include the raw wallet — fine, but they're
  often verbose ("Open marwan's profile") and would benefit from short
  labels.
- Several interactive `<span>` and `<div onClick>` should be `<button>`
  for keyboard nav. Quick grep for `onClick=` on non-button elements:
  - `FriendsDrawer` row's `▸` arrow
  - `RecentBuysTable` row hover area
- Color contrast: `text-neutral-600` on `bg-neutral-950` falls below
  WCAG AA at small sizes. The `text-[9px] text-neutral-600` combo on
  several stat sub-texts is borderline unreadable.
