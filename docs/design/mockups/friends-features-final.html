Friends — final design

Unified storyboard across the 5 screens you picked. No element repeats: the FRIENDS access-mode radio picks the pool's default invite flavor at creation, while the INVITE FRIENDS tab is the ongoing management surface for adding more friends to an existing pool as long as unredeemed codes remain.

01

Find a player — ⌘K / / palette

No persistent search input in the header. From any page, hit / or ⌘K to open the palette. Returns up to 8 results from a server-side pseudo prefix index, ranked by friendship distance (friends first, then strangers). Hitting ↵ navigates to /u/[pseudo-or-wallet]. Privacy on the result row: locked pseudos render with a 🔒.

Profile — respects privacy · friends drawer

Existing ProfileCard gains a clickable N friends pill in the identity stack. Clicking it slides a drawer in from the right with the wallet's accepted friends, filter input, and per-row link to that friend's profile. Privacy: on a private profile that isn't your own, the drawer is hidden — only basic identity (avatar, pseudo, wallet, X handle) + the ADD FRIEND button remain visible.

Create pool — pick the invite flavor

05

Recipient — one-click claim on the pool page

When alice opens the pool page (from a notification, a direct link, or by browsing), the server checks for a stored invite against her wallet. If one exists, this banner replaces the "Checking whitelist…" prompt. One signature triggers the existing redeemInviteCodeWhitelist instruction with the server-stored code+proof, the wallet becomes whitelisted on-chain, and the page refreshes into the normal buy-ticket flow.

What's new under the hood

  • API · GET /api/users/search?q=... — pseudo prefix-search returning up to 8 results.
  • API · POST /api/pool-invite — creator signs tombola:pool-invite:<pool>:<friend>:<nonce>, server allocates one of the creator's unused codes (looked up via localStorage handoff at create-time → server) and stores it against the friend's wallet.
  • API · GET /api/pool-invites/[wallet] — list of pool invites for me. Drives the banner + notifications.
  • API · POST /api/pool-invite/claim — friend signs, server submits the existing redeemInviteCodeWhitelist instruction with the stored code+proof. Returns the on-chain signature.
  • API · DELETE /api/pool-invite — creator revokes an unredeemed invite (returns the code to the pool's unused set).
  • KV · pseudo-index — sorted set keyed by lowercase pseudo prefix → wallet, for prefix scans during search.
  • KV · pool-invite:<pool>:<friend> = { code, proofs, inviter, ts, status }
  • KV · pool-invites-by-wallet:<wallet> = Set<pool> — reverse index for the inbox view.
  • UI · New components: SearchPalette, FriendsDrawer, FriendPicker, PoolInviteBanner. Reuse WalletLink, WalletIdenticon, existing tabs styling from CreatePoolModal.
  • Protocol · Untouched. All invites flow through the existing redeemInviteCodeWhitelist → Whitelisted PDA → buyTicketPrivate chain.
