4 · Recipient — pool page top banner

When a friend opens the pool page and has a server-stored invite, a one-click claim banner replaces the "Connect wallet" prompt:

🎟
You're invited!
marwan reserved a seat for you in this pool · 0.05 SOL/ticket

One signature, redeems server-side stored code+proof, whitelists wallet, refreshes page. Then the normal buy-ticket flow appears.

Best for: power-user / keyboard-driven feel. Search is invisible until invoked; friends live where you already are (profile, pool admin). Inviting can happen at any time over the pool's life, not just at creation.

Backend pieces are identical across all three options:
  • GET /api/users/search?q=… — server-side pseudo prefix search (new)
  • POST /api/pool-invite — creator signs, allocates a code+proof to a friend's wallet (new)
  • GET /api/pool-invite/[wallet] — list invites for me (new)
  • POST /api/pool-invite/claim — friend signs, server-side calls existing redeem flow on their behalf (new)
  • KV schema additions: pseudo-index:* (search), pool-invite:<pool>:<friend> (stored invite)
